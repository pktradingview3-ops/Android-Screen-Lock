# PDR: Android Wallpaper + Lock-Screen Time Personalization App

Status: v0.2 (Phase 1 code written; build verified in CI, device test pending)
Owner: Personal project (not for Play Store release in v1)
Target device for testing: vivo Y31 (2021), Funtouch OS, Android 11/12 based (exact version to be confirmed on device via Settings > About phone)

---

## 1. Goal

Build a simple, transparent Android app that lets the user set a black wallpaper with a large, bold white time display, in several layouts (horizontal and vertical), with optional custom name text. The app must use only supported Android APIs and must not bypass or disable any system security.

## 2. Non-goals (v1)

- No replacement or modification of the system lock screen UI, PIN, pattern, or biometrics.
- No accessibility-service, overlay, device-admin, or root-based hacks to "control" the lock screen.
- No lock-screen widgets (not available on the target device/OS level).
- No Play Store release, ads, analytics, accounts, or network calls.
- No user-uploaded photo backgrounds in v1 (planned for v2).

## 3. Key Technical Constraint (must read)

A static image cannot show a live clock. A wallpaper bitmap is a picture; once set, its time is frozen.

To show the current time on the lock screen, the options are:

| Option | How it works | Pros | Cons |
|---|---|---|---|
| **A. Live wallpaper (WallpaperService)** | App draws the wallpaper (black + time + name) every minute using Canvas. | Real live time; supported Android API; no bitmap spam. | Lock-screen-only live wallpaper is not reliably supported across OEMs. Common setup is "home + lock" together. Must be tested on vivo Y31. |
| **B. Static image on lock screen (WallpaperManager, FLAG_LOCK)** | App renders a PNG with current time and sets it as lock wallpaper. | Supported API (Android 7+). Works on Y31. | Time is frozen at the moment it was rendered. Updating every minute is not practical (battery, flicker, OS throttling). |
| **C. Lock-screen widget** | Android 16+ keyguard widgets. | Official live-time option. | Not available on vivo Y31 / Android 11-12. Not an option for the target device. |

**Recommendation:** Option A as the main path (live time), with Option B as a fallback (static "snapshot" wallpaper, time updated when the user opens the app or changes settings). Final behaviour will be decided after a device test on the Y31 (see section 11, Phase 0).

## 4. Target Platform

- Language: Kotlin (confirmed by user)
- UI: Jetpack Compose (for the app's own screens)
- minSdk: 26 (Android 8.0), so it installs on the Y31 and a wide range of phones
- targetSdk: latest stable at build time
- Build: Gradle (Android Studio standard), no custom native code

## 5. Features (v1)

### 5.1 Lock-screen wallpaper

- Black background (`#000000`) only in v1.
- White, bold time.
- Time format: 12-hour or 24-hour (user setting).
- Optional date line above the time (e.g. `THU, 08 OCT 2026`), toggle on/off.
- Optional custom name / text line, toggle on/off, with max length 20 characters.
- Time updates once per minute, aligned to the minute boundary.

### 5.2 Layouts (from approved mockups, all kept)

Mockups are in `design/wallpaper-mockups/` and generated by `make_mockups.py`.

| ID | Name | Orientation | Notes |
|---|---|---|---|
| L1 | Vertical stack, left | Vertical | Hour above minute, left aligned, date above |
| L2 | Vertical stack, center | Vertical | Hour and minute centered, thin white rule between |
| L3 | Vertical condensed, right | Vertical | Tall, condensed digits, right aligned |
| L4 | Horizontal single line | Horizontal | `HH:MM` on one line, centered, date above |
| L5 | Horizontal wide, dot | Horizontal | Extended digits, dot separator, bottom accent rule |

Layouts are data-driven templates (position, font scale, condense factor, rules). Adding a new layout later means adding a template, not new screen code.

### 5.3 Fonts

- v1 uses one bundled bold sans font (licence must allow bundling; check before shipping).
- Font scaling and horizontal condensing are done in code so the same template works on any screen size.

### 5.4 App lock (v0.2.0)
- Optional PIN (4 to 6 digits) to open TimeWall. Off by default.
- Locks when the app process starts, and when the app comes back to the foreground after more than 30 seconds in the background. A short trip (e.g. to the system wallpaper picker) does not lock it.
- Optional fingerprint (BIOMETRIC_STRONG) as a convenience. The PIN always works too.
- Wrong PIN: 5 consecutive failures start a lockout of 30 s, doubling per further failure, capped at 15 min.
- PIN stored only as a PBKDF2-HMAC-SHA256 hash (120,000 iterations, 16-byte random salt) in app-private SharedPreferences.
- While app lock is on, FLAG_SECURE blocks screenshots and recents previews of TimeWall.
- No in-app PIN reset: resetting without the PIN would be a bypass. Forgotten PIN: Android Settings > Apps > TimeWall > Clear data (this also deletes saved TimeWall settings).
- App lock does NOT protect the system lock screen or the live wallpaper. It only guards TimeWall's own screens.

## 6. Screen Flow

```
[Splash / Home]
   |
   +--> [Layout Picker]  (grid of L1-L5 previews, tap to select)
   |        |
   |        +--> [Editor]  (time format, date on/off, name text, preview)
   |                  |
   |                  +--> [Apply]
   |                          |
   |                          +--> Option A: "Set live wallpaper" (system preview screen, user confirms)
   |                          +--> Option B: "Set as lock screen image" (WallpaperManager, FLAG_LOCK)
   |
   +--> [Settings]  (12/24h default, about, privacy, open-source notice)
   +--> [Help]      (how to set wallpaper on vivo Funtouch OS, why live time may vary)
```

Key UX rules:
- Live wallpaper: the app opens the system preview, and the user confirms there. The app never changes the live wallpaper silently.
- Static snapshot: `WallpaperManager.setBitmap` applies immediately (no system preview). The UI says so and warns that the time will not update.
- Preview always shows the real rendering engine output (same code path as the live wallpaper).

## 7. Architecture

```
app/
  ui/            Compose screens (LayoutPicker, Editor, Settings, Help)
  domain/        Layout templates, time formatter, settings models (pure Kotlin, unit-tested)
  render/        Canvas renderer: draws black bg + text using layout template (shared by preview, live wallpaper, static export)
  wallpaper/     WallpaperService subclass (live), tick scheduler (minute-aligned Handler/AlarmManager-free approach)
  apply/         Static export (render to Bitmap -> WallpaperManager.setBitmap(FLAG_LOCK))
  data/          Settings persistence (SharedPreferences). No network, no database in v1.
```

Design principles:
- One renderer, three uses: UI preview, live wallpaper, static export. Output must match.
- Rendering is cheap: a single black canvas and a few text draws. Redraw only on minute change, on visibility change, or on settings change.
- Live wallpaper pauses drawing when not visible (`onVisibilityChanged`) to save battery.

## 8. Permissions and Settings (transparent handling)

| Permission / capability | Needed? | Why | How handled |
|---|---|---|---|
| `SET_WALLPAPER` | Yes (normal, auto-granted) | Set static lock wallpaper and open live wallpaper picker | Declared in manifest; no runtime prompt |
| `BIND_WALLPAPER` | Yes (system-only, declared on service) | Required for live wallpaper service | Declared on the service; user chooses it in system UI |
| `INTERNET` | **No** | No network features in v1 | Not declared |
| Storage / Photos | **No** in v1 | No photo backgrounds in v1 | When added in v2, use Android Photo Picker (no broad storage permission) |
| Notifications | **No** | Not used | Not declared |
| Accessibility service | **No** | Not allowed for this purpose | Not used |
| Overlay (`SYSTEM_ALERT_WINDOW`) | **No** | Not allowed for this purpose | Not used |
| Device admin | **No** | Not allowed for this purpose | Not used |
| `USE_BIOMETRIC` | Yes (normal, auto-granted; merged from `androidx.biometric`) | Optional fingerprint unlock for app lock | Only used when the user turns on fingerprint; PIN always works |
| Battery optimization exemption | **No** (default) | Live wallpaper should not need it | Only ask if device testing proves it is needed, and explain why in-app |

Settings the user must do manually (app shows step-by-step help, never automates them):
- Choose the live wallpaper in system wallpaper picker (Option A).
- On Funtouch OS, check that the wallpaper applies to the lock screen (menu names vary by OS version).
- Keep the app's battery usage as "Unrestricted" only if the live wallpaper gets killed by the OS (test first).

## 9. Privacy

- No accounts, no analytics, no crash reporting, no network calls in v1.
- Only local data: layout choice, time format, date toggle, name text. If app lock is on: a salted PIN hash, lockout counter and the fingerprint toggle (all on the device).
- The app will include a short privacy note in Settings.

## 10. Quality and Testing

### 10.1 Unit tests
- App lock rules: PIN validation, lockout schedule and cap, PBKDF2 hash/verify, 30-second grace logic (`app/src/test/.../security`).
- Time formatter: 12h/24h, midnight, noon, leap-year date, timezone change.
- Layout templates: text fits within 1080x2400 and safe area for every layout (automated bounds check, same logic as `make_mockups.py`).
- Name text: max length, empty name, emoji/Unicode handling (fallback to plain text if glyph missing).

### 10.2 Device tests on vivo Y31 (manual checklist)
- Lock screen shows the wallpaper after applying Option A and Option B.
- Live time updates at each minute change while screen is on.
- Behaviour after screen off for 10+ minutes (Doze): time correct when unlocked.
- Behaviour after device reboot.
- Battery use over 1 hour idle (target: low, no wake locks).
- Display after rotation, Always-On (if present), and in both light and dark system themes.
- Not affected by fingerprint / PIN screen (the app lock never changes the live wallpaper).
- App lock checklist: see `docs/device-test.md`, Test E.

### 10.3 Performance targets
- Renderer draw time under 16 ms on the Y31.
- App install size under 10 MB.
- No wake locks held by the app.

## 12. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Live wallpaper does not show on the lock screen alone on Y31 | Live time may need "Home + Lock" | Document this; fall back to Option B; Phase 0 test decides |
| Funtouch OS kills the wallpaper service in the background | Time stops updating | Redraw on screen-on/visibility; show help on battery settings |
| Y31 Android version is old (Android 11/12) | Some newer APIs are not available | minSdk 26 and API-level checks; no Android 13+ only APIs in v1 |
| Font licence | Legal | Use a font with a permissive licence; record licence in repo |
| User expects a fully custom system lock screen | Scope confusion | Clear "What this app can and cannot do" text in Help and README |
